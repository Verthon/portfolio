**Status:** Alpha since March 2026, after a technical preview from October 2025

<Heading tag="h2" id="overview" linkLabel="Link to heading: Overview">Overview</Heading>

- Runs ESLint v9+ plugins and custom JS/TS rules inside Oxlint, alongside 650+ native Rust rules
- [Alpha since 2026-03-11](https://oxc.rs/blog/2026-03-11-oxlint-js-plugins-alpha) - upstream calls it ready for adoption in real-world projects
- Conformance as of the alpha post: 100% of ESLint's own 33,006 rule tests, and 99.6-100% on react-hooks, ESLint Stylistic, Testing Library, SonarJS and e18e

<Heading tag="h2" id="known-issues-and-tradeoffs" linkLabel="Link to heading: Known Issues & Tradeoffs">Known Issues & Tradeoffs</Heading>

- No custom template syntax (Vue, Svelte, Angular) - tracked in [oxc#19918](https://github.com/oxc-project/oxc/issues/19918)
- No custom type-aware rules - typescript-eslint's rules exist natively via [type-aware linting](https://oxc.rs/docs/guide/usage/linter/type-aware.html)
- Windows out-of-memory errors: [#19395](https://github.com/oxc-project/oxc/issues/19395) and [#19480](https://github.com/oxc-project/oxc/issues/19480) closed May-June 2026, but a repeat was reported on 1.68.0, and [oxc#19918](https://github.com/oxc-project/oxc/issues/19918) says a full fix needs an allocator overhaul
- JS rules can't match native Rust rules on speed

<Heading tag="h2" id="adoption-considerations" linkLabel="Link to heading: Adoption Considerations">Adoption Considerations</Heading>

- **New Projects**: Adopt. Lean on native rules, add JS plugins for the gaps. Hold off if you lint Vue, Svelte or Angular templates.
- **Existing Projects**: Trial a full switch with the [ESLint migration guide](https://oxc.rs/docs/guide/usage/linter/migrate-from-eslint.html). If a plugin blocks you, [eslint-plugin-oxlint](https://www.npmjs.com/package/eslint-plugin-oxlint) still lets you offload the rules Oxlint covers and keep ESLint for the rest.
