<Alert variant="info" marginBottomInRems={2}>
  **Who is this for?** Only projects using `coverage.provider: 'istanbul'` in
  Vitest (or any other source-instrumentation pipeline). If you're on Vitest's
  default `provider: 'v8'`, this tool does not apply - V8 coverage is collected
  by the engine at runtime and never goes through a source-rewriting step.

<Heading tag="h2" id="overview" linkLabel="Link to heading: Overview">Overview</Heading>

- Istanbul-compatible coverage instrumentation built on the [Oxc](https://oxc.rs) parser
- Before it, any tool on `oxc_parser` had to pull in SWC or Babel to emit coverage
- Verified against `istanbul-lib-instrument` on 25 shared fixtures and 1,061 real TS/TSX/JS files from a production React monorepo
- Ships a Rust crate, Node.js bindings (napi-rs, 7 native platforms + WASI), and a standalone CLI
- Vitest integration via `createOxcInstrumenter` - the [`coverage.instrumenter` option](https://vitest.dev/config/coverage.html#coverage-instrumenter) shipped experimentally in [Vitest 4.1.5](https://github.com/vitest-dev/vitest/pull/10119)

<Heading tag="h2" id="performance" linkLabel="Link to heading: Performance">Performance</Heading>

8-11x faster than babel-plugin-istanbul, 13-15x faster than swc-plugin-coverage-instrument (Rust/WASM), 25-30x faster than istanbul-lib-instrument - upstream's own numbers as of v0.3.8, measured end-to-end on real libraries (React, lodash, vue, d3, three). Upstream has since stopped publishing figures and asks you to [run the comparison script](https://github.com/fallow-rs/oxc-coverage-instrument/blob/main/ARCHITECTURE.md#benchmarks) locally.

<Heading tag="h2" id="known-issues-and-tradeoffs" linkLabel="Link to heading: Known Issues & Tradeoffs">Known Issues & Tradeoffs</Heading>

- Seven documented divergences from istanbul ([list](https://github.com/fallow-rs/oxc-coverage-instrument/blob/main/crates/oxc_coverage_instrument/README.md#differences-from-istanbul-lib-instrument)). Two change your numbers: `??=`/`||=`/`&&=` and optional-chain short-circuits are both counted as branches, so branch % drops after switching. A strict Istanbul profile disables the extensions.
- Vitest's `coverage.instrumenter` option works in 4.1.5+ but is still flagged experimental in 5.0 - no stabilization date announced
- Source-instrumentation is the main path. V8 ingestion is a separate crate (`oxc_coverage_v8`, Rust-only, v0.4.x) - see below

<Heading tag="h2" id="adoption-considerations" linkLabel="Link to heading: Adoption Considerations">Adoption Considerations</Heading>

- **New Projects**: strong drop-in candidate if you're on Vitest 4.1.5+ with the Istanbul provider
- **Existing Projects**: rebaseline branch-coverage thresholds before swapping, since logical assignments and optional chains add branches that previously went uncounted. Or start on the strict Istanbul profile for a like-for-like comparison.
- Watch [oxc#21108](https://github.com/oxc-project/oxc/issues/21108): as of July 2026 the Oxc lead proposed moving the transform into oxc and exposing it to Vitest via rolldown, which would make the standalone package unnecessary

<Heading tag="h2" id="v8-coverage-context" linkLabel="Link to heading: V8 coverage context">V8 coverage context</Heading>

`oxc-coverage-instrument` is on the source-instrumentation path (the Istanbul lineage). The V8-coverage path - runtime collection via the Inspector protocol - is a separate ecosystem:

- [`@vitest/coverage-v8`](https://vitest.dev/guide/coverage) is the actively maintained V8 provider. Since v3.2.0 it uses AST-based remapping that produces Istanbul-equivalent reports, which closed the old "V8 is faster but less precise" gap
- [`c8`](https://github.com/bcoe/c8) still works but is in maintenance mode, and Vitest docs now point at `@vitest/coverage-v8` instead
- Node 22+ ships [`--experimental-test-coverage`](https://nodejs.org/api/test.html) with built-in lcov/text reporters - usable but emits raw V8 output, so third-party tools are still needed for Istanbul normalization
- [`v8-to-istanbul`](https://github.com/istanbuljs/v8-to-istanbul) is the bridge from V8's raw output to Istanbul format: 40M weekly downloads, but no npm release since 9.3.0 (June 2024). A Rust port, [`oxc_coverage_v8`](https://github.com/fallow-rs/oxc-coverage-instrument/blob/main/crates/oxc_coverage_v8/README.md), shipped from the same repo in May 2026, with a Rust API only and no Vitest wiring.
